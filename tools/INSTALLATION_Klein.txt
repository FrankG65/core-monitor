KERN-MONITOR (Core Monitor) – Paket "Lite" (Klein)
==================================================

Dieses Paket enthält nur die Quelltexte (keine fertigen Programme, kein Python). Das hält es klein und übersichtlich,
und alles wird auf dem Ziel-PC frisch aus den Quelltexten erzeugt. Benötigt wird nur, was man nutzen möchte:

  Was                         Nötig für                                    Ohne das ...
  --------------------------  -------------------------------------------  ----------------------------------------------
  1. Python 3.11 oder neuer   ALLES (Server, Seite, Python-Verfahren)      läuft nichts
  2. Internet (einmalig)      Python-Pakete per pip                        start.bat bricht mit Hinweis ab
  3. .NET SDK 10              Rechenverfahren "C#" und "C# SIMD"           diese zwei sind ausgegraut
  4. Rust (rustup)            Rechenverfahren "Rust" und "Rust SIMD"       diese zwei sind ausgegraut
  5. Visual Studio C++        C, C++, Assembler, GPU                       diese sind ausgegraut
  6. Grafikkartentreiber      GPU-Rechenverfahren                          ausgegraut

Für die SIMD-Rechenverfahren und Assembler braucht die CPU AVX2 (fast alle seit ca. 2015); sonst sind sie ausgegraut.
Die Seite erkennt CPU und Grafikkarte beim Start und zeigt unter "System", was verfügbar ist und warum nicht.

SCHRITT FÜR SCHRITT
-------------------
1) Python installieren (Pflicht)
   - https://www.python.org/downloads/windows/  -> "Windows installer (64-bit)", Version 3.11 oder neuer.
   - Im Installer unbedingt "Add python.exe to PATH" anhaken.
   - oder in der Eingabeaufforderung:  winget install Python.Python.3.11
   Prüfen:  python --version          (muss 3.11 oder höher melden)
   Die Pakete (requirements.txt: fastapi, uvicorn, psutil, numpy, gmpy2, mpmath; dazu optional numba)
   installiert start.bat beim ersten Start selbst. Von Hand:  python -m pip install -r requirements.txt numba

2) .NET SDK 10 (optional, für C#)
   - https://dotnet.microsoft.com/download   -> ".NET 10 SDK", x64
   - oder:  winget install Microsoft.DotNet.SDK.10
   Prüfen:  dotnet --version          (10.x)

3) Rust (optional, für Rust)
   - https://rustup.rs  -> rustup-init.exe ausführen, Standardeinstellungen übernehmen
   - oder:  winget install Rustlang.Rustup
   Rust braucht unter Windows den Linker aus Schritt 4 (Visual Studio C++).
   Prüfen:  cargo --version

4) Visual Studio mit C++ (optional, für C, C++, Assembler und GPU; auch für Rust nötig)
   - "Build Tools für Visual Studio" (kostenlos) oder Visual Studio Community:
     https://visualstudio.microsoft.com/de/downloads/
   - Im Installer die Arbeitsauslastung "Desktopentwicklung mit C++" wählen
     (enthält Compiler cl, Assembler ml64, Windows SDK mit dem Shader-Compiler fxc).
   - oder:  winget install Microsoft.VisualStudio.2022.BuildTools --override "--add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --passive"
   Prüfen: native\build.bat ausführen -> "C, C++, assembler and GPU compiled."

5) Grafikkarte (optional, für GPU)
   - aktuellen Treiber von NVIDIA, AMD oder Intel installieren. Nötig ist Direct3D 11 (alle Karten seit ca. 2010).

STARTEN
-------
1. ZIP entpacken, z. B. nach C:\CoreMonitor.
2. start.bat doppelklicken. Beim ersten Start werden die Python-Pakete installiert und – soweit die Werkzeuge aus
   Schritt 3–5 vorhanden sind – C#, Rust, C, C++, Assembler und GPU übersetzt (1–3 Minuten).
3. Der Browser öffnet http://127.0.0.1:8000. Der Server ist nur auf diesem PC erreichbar.
Beenden: das schwarze Fenster schließen. Anderer Port: vorher  set PORT=8001

PROBLEME?
---------
- "Python wurde nicht gefunden": Schritt 1 wiederholen, dabei "Add to PATH" anhaken; neue Eingabeaufforderung öffnen.
- Ein Rechenverfahren ist ausgegraut: oben auf der Seite "System" aufklappen – dort steht der Grund.
- Ohne Internet: Auf einem PC mit Internet das Paket "Full" (Komplett) bauen (export_full.bat,
  ergibt export\CoreMonitor_Full_<Datum>.zip) und dieses verwenden.
- Sprache: oben auf der Seite DE | EN umschalten (Voreinstellung = Englisch; die Wahl wird gemerkt).
  Startsprache des Servers: vorher  set KM_LANG=de  bzw.  set KM_LANG=en
- Beschreibung und Projektbericht liegen zweisprachig bei: README.de.md / README.md,
  Projektbericht_Parallelisierung.pdf (Deutsch) / Project_Report_Core_Monitor.pdf (Englisch).
- Fachbegriffe (numba, SIMD, CCX, Kardioide ...) sind in README.de.md im Abschnitt "Begriffe kurz erklärt" erklärt, mit Links.
- Ein roter Hinweis oben auf der Seite bedeutet: Der Server hat Anfragen von außen abgewiesen (z. B. eine
  fremde Webseite). Ausgeführt wurde nichts; Details in logs\security.log. Lizenz: LICENSE, THIRD_PARTY_NOTICES.md.

VIRENSCANNER (wichtig, aber kein Grund zur Sorge)
-------------------------------------------------
Virenscanner (z. B. Microsoft Defender, Trend Micro) und Windows SmartScreen können bei diesem Programm Alarm
schlagen oder Teile blockieren – das ist ein Fehlalarm und unbegründet. Die Programme prüfen nach Verhaltensmustern,
und der Kern-Monitor hat einige, die auch Schadprogramme zeigen:
  - selbst übersetzte .exe-Dateien ohne digitale Signatur und ohne "Bekanntheit" (C#, Rust, C, C++, Assembler, GPU),
  - frisch entpackte, unbekannte Dateien aus einem ZIP (aus dem Internet, per Mail oder USB-Stick),
  - viele gleichzeitig gestartete Prozesse (bis zu 48 Python-Worker) und 100 % Auslastung aller Kerne
    (ähnlich wie ein Krypto-Miner).
Mögliche Anzeichen:
  - "Zugriff verweigert" beim ersten Start eines Rechenverfahrens oder ein langsamer erster Start,
  - eine .exe wird in Quarantäne verschoben oder gelöscht -> das Rechenverfahren erscheint ausgegraut
    mit dem Hinweis "Programm fehlt – vermutlich von einem Virenscanner ...",
  - Warnung "Der Computer wurde durch Windows geschützt" (SmartScreen).
Was tun:
  1. Ein paar Sekunden warten bzw. start.bat neu starten – der Monitor wiederholt einen gesperrten Start
     bis zu 10 Sekunden lang selbst; meist ist die Prüfung dann abgeschlossen.
  2. Vor dem Entpacken: Rechtsklick auf die ZIP-Datei -> Eigenschaften -> "Zulassen" anhaken -> OK.
     Bei SmartScreen: "Weitere Informationen" -> "Trotzdem ausführen".
  3. In der Quarantäne des Virenscanners nachsehen und die Datei wiederherstellen.
  4. Den Ordner des Kern-Monitors im Virenscanner als Ausnahme eintragen – NUR, wenn das Paket aus
     vertrauenswürdiger Quelle stammt (selbst gebaut oder direkt vom Ersteller erhalten).
  5. Wer sichergehen will: einzelne .exe-Dateien bei https://www.virustotal.com prüfen lassen,
     oder das Paket "Lite" (Klein) nehmen und alles selbst aus den beiliegenden Quelltexten übersetzen.
Den Virenscanner bitte NICHT abschalten. Die Python-Rechenverfahren (numba, numpy) und Pi laufen auch dann,
wenn alle .exe-Dateien blockiert sind.
